# Queuest 퀘스트 시스템

목표는 이야기, 할 일은 퀘스트, 일정은 퀘스트를 수행하는 시간이다.
목적은 처리량 경쟁보다 현재 행동이 어떤 목표로 이어지는지 기억하게 하는 것이다.

## 세계와 목표

- 원정(Project): 달성하려는 성과를 담는 프로젝트.
- 챕터/스테이지(Milestone): 원정의 중간 성과. 현재 스테이지 이름을 유지한다.
- 퀘스트(Task): 실행하고 완료 여부를 확인하는 행동 단위.
- 수행 조건: Subtask 등에 해당하는 퀘스트의 완료 조건.
- 인박스: 아직 목표나 프로젝트를 정하지 않은 빠른 기록.

목표, 이유, 다음 행동을 함께 보여준다. 현재 목표는 퀘스트의 문자열로 저장하며,
독립 Goal 엔티티 및 프로젝트 공통 목표는 후속 범위다.

## 조합 가능한 분류

| 축 | 값 | 의미 |
|---|---|---|
| 목표와의 관계 | 메인 / 서브 | 필수 작업 / 선택적 개선·탐색 |
| 반복 주기 | 단발 / 일일 / 주간 | 수행 주기 |
| 도전 성격 | 일반 / 보스 / 레이드 / 기간 한정 이벤트 | 일반 작업 / 중요한 관문 / 협동 도전 / 기간 내 참여 기회 |

메인+주간, 메인+보스처럼 조합한다. 출처로 메인/서브를 결정하지 않는다.
기존 작업에 소급 적용하지 않으며 편집 시 기본 제안은 서브·단발·일반이다.
보스는 크기보다 명시적인 성공 조건으로 정의한다. 레이드는 협동의 의미이며 현재
참여자 관리나 공동 진행률 기능을 뜻하지 않는다.

## 외부 서비스의 역할

| 외부 항목 | 기본 해석 |
|---|---|
| Jira Epic | 챕터 또는 연속 퀘스트. 규모에 따라 원정으로 조정 가능 |
| Jira Task | 메인 또는 서브 퀘스트 |
| Jira Subtask | 상위 퀘스트의 수행 조건 |
| GitHub Issue | 퀘스트 또는 기존 Jira 퀘스트의 연결 항목 |
| GitHub PR | 결과물과 검수 근거. 리뷰 자체가 독립 행동이면 별도 퀘스트 |
| Calendar Event | 예정된 활동 또는 출정 시간 |
| Reminder | 행동이면 단발·반복 퀘스트, 단순 알림이면 보조 정보 |

같은 일을 설명하는 Jira Task, Issue, PR, 일정은 하나의 로컬 퀘스트에 연결한다.
자동 추정으로 병합하지 않는다. 일정 종료나 PR 머지만으로 목표 완료를 판정하지
않는다. 완료는 기존 todo → doing → review → done과 사람의 확인을 따른다.
외부 주최 해커톤·컨퍼런스·베타 테스트 주간은 운영사 이벤트에 대응한다.
일반 회의는 예정된 활동이다. 반복 분류와 반복 회차 생성은 구분한다.

## 추적과 보상

할 일 화면에서 원정 → 스테이지 → 현재 퀘스트, 목표, 이유, 다음 행동, 성공 조건,
수행 예정 시간을 연결한다. 추적 대상은 사용자가 선택하고 완료된 작업은 제외한다.
추적 개수는 현재 제한하지 않되 소수의 메인 퀘스트에 집중하는 사용을 권장한다.
XP는 기존 로컬 태스크 기반 계산을 유지한다. 연결 항목 추가는 보상을 늘리지 않는다.
같은 작업을 다른 로컬 퀘스트로 생성한 경우의 자동 중복 판별은 아직 없다.
향후 반복 회차는 별도 완료 이력을 보존해야 한다. 미달성·중단에 벌점을 주지 않는다.

## 이번 구현

- Task.quest에 목표·이유·다음 행동·성공 조건, 세 분류 축, 추적 여부 저장.
- 여러 종류의 HTTP(S) 원본 링크와 로컬 수행 예정 시각 수동 편집.
- SQLite에 nullable quest_context 열을 추가하는 비파괴적·재실행 가능한 마이그레이션.
- 프로젝트 보드와 전역 할 일 추적 영역에 문맥 표시. 기존 작업·원본 링크 보존.
- 연결 항목만으로 상태나 XP를 변경하지 않음.

## 후속 구현과 완료 조건

- 공통 목표: 원정 목표 수정이 연결된 퀘스트에 일관되게 반영된다.
- 수행 조건: Subtask 체크와 부모 완료 조건, 순환 없는 계층을 지원한다.
- 가져오기: Epic/Task/Subtask 관계, PR 결과물, Calendar와 Reminder를 보존한다.
- 연결 식별자: provider/connection/external ID로 연결을 제안하고 사용자가 결정한다.
- 반복 회차: 시간대·주 시작일을 명시하고 이력 보존과 중복 생성 방지를 검증한다.
- 일정: 시작/종료·종일·시간대·취소·변경을 보존한다. 현재 단일 로컬 시각은 동기화가 아니다.
- 이벤트: 참여 기간과 종료 처리. 보스/레이드: 성공 조건과 공동 기여 검증.
- 보상: 회차별 중복 보상 방지, 챕터/보스 칭호와 주간 회고.

## 예시

원정: Queuest 베타 출시 → 스테이지: 외부 작업 통합 → 메인 퀘스트: Jira 작업 가져오기.
Jira Task와 GitHub Issue를 연결하고 PR을 결과물로 붙인다. 성공 조건은 인증·조회·중복
방지 확인, 다음 행동은 중복 방지 테스트 작성이다. Calendar 집중 시간을 연결한다.
첫 사용자가 연결부터 퀘스트 완료까지 성공하는 것이 보스의 성공 조건이다.

## Jira 백로그 수락과 PR 검토

Jira 보드 백로그 범위에서 가져온 퀘스트는 `quest.acceptance: pending`으로 저장한다.
진행 상태는 `todo`지만 별도 미수락 목록에 표시한다. 수락 버튼으로 `accepted`를 저장한
뒤 대기 보드에 나타난다. 필드가 없는 기존 퀘스트는 수락된 것으로 취급한다.
미수락 퀘스트는 진행률·XP·추적에서 제외하고 상태 전환을 막는다. 수락은 로컬 동작이며
Jira의 스프린트·상태를 바꾸지 않는다. 보드 ID가 설정되어 있으면 일반 프로젝트 범위에서도
해당 보드의 백로그 여부를 확인해 미수락으로 저장한다. 보드 ID가 없으면 프로젝트
범위에서는 백로그 여부를 구분하지 않는다.

할 일 화면의 GitHub PR 목록은 `gh` 계정에 리뷰 요청된 열린 PR을 최대 100개 보여준다.
PR 확인은 원본 링크로 연결하며 작업을 자동 생성하거나 완료시키지 않는다.
