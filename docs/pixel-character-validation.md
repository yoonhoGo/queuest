# 도트 캐릭터 엔진 검증

## 환경·실행

- 2026-09-17, macOS 27.0 (arm64), Apple M3 Pro, 논리 코어 12.
- Node 24.10.0, Three.js 0.186.0, TypeScript 6.0.3, Vite 8.2.2.
- Chrome 153.0.8010.48 headless, ANGLE Metal / WebGL2, DPR 2, 1280×900. Aside의 실제 브라우저 화면에서도 버튼과 프리뷰를 조작·검수했다.
- 최종 성능 측정은 Vite 프로덕션 빌드를 `http://127.0.0.1:1431`에서 제공했다. 개발 서버와 별도로 실행했다.
- `npm ci`: 통과. `npm run check`: 모든 workspace TypeScript 검사와 기존 desktop 빌드 통과. `npm test`: 기존 117개 통과. `npm run test:pixel`: 새 단위 테스트 6개 통과. `npm run build:pixel`: 엔진 JS/선언 및 데모 프로덕션 빌드 통과.
- 엔진을 실제 `.tgz`로 패키징해 저장소 밖 임시 프로젝트에 설치하고, `skipLibCheck:false` TypeScript 검사와 잘못된 API 인자의 타입 거절을 확인했다. 루트에서 배포용 `@queuest/pixel-character` import도 확인했다.

재현 명령:

```sh
npm ci
npm run build:pixel
npm run test:pixel
npm run preview --workspace @queuest/pixel-character-demo -- --port 1431
# 다른 터미널:
PIXEL_URL=http://127.0.0.1:1431 PIXEL_BENCHMARK=1 npm run smoke:pixel
```

## 수치·동작 검사

2026-09-17 북마크 분리 후에도 `main` + `pixel`만으로 `npm run check`, `npm run build:pixel`, 단위 테스트 6개와 프로덕션 브라우저 스모크를 다시 통과했다. 데모 컨트롤은 데모 내부로 옮겼으며 `component` 북마크의 파일을 가져오지 않는다. 재검증 이미지·결과는 `/tmp/queuest-pixel-separated`에 생성했다. 아래 성능 측정은 렌더링 코드가 동일한 분리 전 측정이며, 북마크 분리 후 성능 측정을 반복한 결과는 아니다.

단위 테스트는 17개 파라미터의 min/max 조합 **131,072개**에서 모든 길이가 유한한 양수이고 `head:height=1:3`, `neck+torso+pelvis+thigh+calf+foot=2H`임을 확인한다. 기본 프리셋, 각 항목 최소/최대, 전체 최소/최대의 실제 메시와 관절도 검사했다. 중립 head 메시 높이·정수리와 발바닥 위치, 팔/다리 관절 간 실제 월드 거리, 관절 스케일 (1,1,1), 반복 변경 후 정확한 복원, JSON round trip/실패 원자성, 점프 유지, 보행 30/60/120Hz 일관성을 포함한다.

[브라우저 원시 결과](pixel-character-smoke.json)의 렌더 검사는 동기 readPixels를 **검사 시에만** 사용했다. 엔진의 정상 frame 경로에는 GPU readback이 없다.

화면 검수에는 저장소의 승인된 `previews/retro/dist/style.css`와 디자인 시스템의 공용 토큰·타이틀바·각진 윤곽·버튼·포커스 패턴을 대조했다. 기존 캐릭터 완료 카드나 퀘스트 데이터에 적용한 변경은 없다. 체크무늬·가이드·동작 패널은 기술 데모의 조작 요소이며 기존 캐릭터 탭을 복제한 화면이 아니다.

`smoke:pixel`은 `/tmp/queuest-pixel-character`에 네 가지 크기의 전체 화면, 정면·측면·후면·가이드 PNG를 생성한다. 최종 실행 당시의 경로는 `/tmp/queuest-pixel-character-final`이었다. 이미지에 직접 API로 설정한 검증 상태가 포함되므로 일부 UI 선택값과 포즈가 다를 수 있다. 실제 클릭·슬라이더 검사는 별도로 수행한다.

## 성능 조건과 해석

[24개 조건의 원시 측정 결과](pixel-character-benchmark.json)에 환경과 프레임 간격 중앙값/p95, CPU 애니메이션 중앙값/p95, 체형 갱신 중앙값/p95, 전체 패스 드로 콜·삼각형 수, GPU 중앙값·표본 수를 기록했다.

- 1·10·50개 × 128·256 × 경계 OFF/ON × 기본/혼합 체형. 조건마다 워밍업 30프레임, 기록 120프레임.
- 하나의 WebGL2 컨텍스트와 같은 30H 정사영 화면을 공유한다. 캐릭터 수에 따라 zoom하지 않는다. 각 캐릭터의 보행 속도·위상·시선·방향은 독립적이다.
- ON은 outline=true, depth/normal=.3. OFF는 셋 모두 꺼짐. 명암 단계와 팔레트 강도는 동일하다.
- 혼합 조건은 네 프리셋을 섞고, 30프레임마다 머리 너비와 다리 배분을 변경해 외형 및 rest 갱신을 함께 측정한다. 기본 조건은 체형을 바꾸지 않는다.
- `renderer.info.autoReset=false`와 프레임당 한 번 reset으로 다중 패스 통계를 합산한다. 표의 드로 콜/삼각형은 프레임 평균을 정수로 반올림했다. 깜빡임 동안 눈 하이라이트가 숨겨져 약간 달라진다.
- CPU 애니메이션 시간은 체형 갱신 시간을 제외한 캐릭터 update 비용이며 포즈 적용·지면 보정도 포함한다. 브라우저 타이머의 약 0.1ms 양자화 때문에 아주 짧은 측정은 0.00ms로 나타날 수 있다. 비용이 없다는 뜻이 아니다.
- GPU는 유효한 비동기 `EXT_disjoint_timer_query_webgl2` 표본만 기록했다. JS `render()` 실행시간으로 대체하지 않았다.
- 프레임 간격은 RAF와 표시 동기화의 영향을 포함한다. 약 16.7ms가 나와도 GPU가 16.7ms를 사용했다는 뜻이 아니다. 이 단일 기기 결과로 FPS 보장이나 최적화 개선율을 주장하지 않는다.
- 50개가 작은 한 타깃에 들어가는 장면이다. 50개의 독립적인 256² 초상이나 50개의 canvas를 렌더링한 결과로 해석하면 안 된다. 인스턴싱·캐릭터 간 GPU 리소스 pooling은 아직 없다.

## 남은 한계

- GLB 로딩·범용 리타기팅·임의 모델의 체형 조절·외부 목표 IK는 구현하지 않았다. 어댑터 계약과 적용 제한만 제공한다.
- 픽셀 경계 자글거림, 보행의 잔여 발 미끄러짐, 정확한 측면에서 반대편 팔다리 가림이 남는다. 가시성·접지 보정을 구현했지만 전신 자기 충돌이나 물리는 없다.
- 수동 관절 포즈는 제한 범위 안에서도 몸과 교차할 수 있다. 중립 가이드는 일반 애니메이션 자세의 실제 머리 높이를 재는 도구가 아니다.
- 화면에 맞추기는 명시적 카메라 재설정이다. 그 후 더 크게 키우면 다시 맞춰야 한다. 실제 이동은 카메라 추적/월드 충돌을 제공하지 않는다.
- 128에서는 얼굴 디테일이 더 적다. 팔레트는 RGB 단계 제한이며 수작업 팔레트 LUT나 temporal 안정화가 아니다.
- Vite의 단일 데모 JS는 약 783KB(전송 gzip 약 211KB)이며 500KB chunk 경고가 남는다. WebGL 엔진과 React를 포함한 크기이며 빌드 오류는 아니다. 실제 호스트는 필요 화면에서 lazy loading할 수 있다.
- 브라우저 검증이며 Tauri 네이티브 앱·사용자 SQLite·Keychain을 시험한 결과가 아니다. Safari·Firefox·모바일 GPU, 장시간 메모리 soak, context-loss 복원은 검증하지 않았다. 탭 숨김 이벤트 처리 코드는 구현했지만 별도 실제 비활성 탭 장기 복귀 시나리오는 수행하지 않았다.
